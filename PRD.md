# PRD — NOIR 3D Fashion Website

## Project Goal
Build and improve a premium, futuristic 3D fashion e-commerce website named NOIR.

## Design Direction
- Premium futuristic techwear aesthetic.
- Black, metallic blue and dark backgrounds.
- Cinematic lighting and smooth transitions.
- High-quality 3D product presentation.
- Minimal, premium typography.
- Inspired by high-end interactive 3D websites, but with original branding.

## Core Requirements

### 1. Homepage
- Premium animated hero section.
- Interactive 3D fashion product.
- Smooth GSAP scroll animations.
- Responsive navigation.
- Clear shopping call-to-action.

### 2. 3D Experience
- High-quality 3D product models.
- Smooth rotation and interaction.
- Mouse movement effects on desktop.
- Touch-friendly interactions on mobile.
- Optimized loading and rendering.

### 3. Product Experience
- Premium product cards.
- Product detail experience.
- Smooth popup animations.
- Product images must never be cropped incorrectly.
- Responsive product layouts.

### 4. Responsive Design
- Mobile-first implementation.
- Support phones, tablets, laptops and desktops.
- No horizontal overflow.
- No clipped products or popup content.
- Proper typography and touch targets.
- Optimize animations for mobile performance.

### 5. Performance
- Optimize 3D model loading.
- Avoid unnecessary re-renders.
- Optimize images and animations.
- Avoid console errors.

### 6. Quality Assurance
- Check all navigation links.
- Test all interactive elements.
- Fix layout glitches.
- Check responsive breakpoints.
- Run the production build.
- Fix TypeScript and build errors.

## Ralph Loop Working Rules

1. Inspect the existing project before making changes.
2. Never rebuild working sections unnecessarily.
3. Preserve the existing visual identity.
4. Make changes incrementally.
5. Do not remove existing features without justification.
6. Test changes before marking tasks complete.
7. Do not claim a feature works without verification.
8. Prioritize mobile responsiveness.
9. Avoid unnecessary dependencies.
10. Never expose API keys or secrets.

## Definition of Done

- Website builds successfully.
- No critical runtime errors.
- Main navigation works.
- 3D interactions work.
- Mobile layout works correctly.
- No horizontal overflow.
- Product popups are fully visible.
- Existing functionality is preserved.

## Execution Strategy

First inspect the entire existing codebase.
Identify incomplete features and actual bugs.
Create a prioritized task list.
Implement and verify improvements one by one.
Do not stop until all applicable requirements are completed or a genuine blocker is documented.
